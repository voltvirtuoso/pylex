Pylex documentation

Pylex is an open-source Python OCR package and command-line tool. It reads text from images and scanned PDFs, and adds an invisible, searchable text layer to a PDF while keeping the original page untouched. The same engine is available as a Python library that returns text, confidence and position for every line.

It is built for pages where plain OCR struggles: large, dense or rotated documents such as engineering drawings, where small labels sit between symbols and PDF pages carry a rotation flag.

Two ways to use it

Command line Python SDK
Best for Folders of scans, one-off jobs, scripts Applications, services, notebooks
Start with pylex scan.pdf extract_text("page.png")
Reference CLI reference Python SDK

Both share one install and one set of models.

Sixty seconds

python -m pip install pylex-ocr
pylex doctor --install        # detects your CPU or NVIDIA GPU and installs the right runtime
pylex scan.pdf                # writes scan.ocr.pdf

Hardware profiles (CPU, Intel, NVIDIA CUDA 12 and 13) and what is and is not supported are covered in Installation.

When to choose something else

Pylex is not a general document-conversion suite. If you need PDF/A output, deskewing and clean-up, OCRmyPDF is the established choice and has a PaddleOCR plugin. Pylex is not a handwriting recognizer, a layout or table reconstruction engine, or a hosted service. See Limitations.

Installation

Pylex needs an OCR runtime that matches your hardware, and the right pip package is different for a laptop CPU, an Intel server, and an NVIDIA GPU. This page shows the one command for each, and how to let Pylex pick for you.

The distribution on PyPI is pylex-ocr. The Python module and the command are both pylex. (The name pylex on PyPI belongs to an unrelated project, so never run pip install pylex.)

Requirements: Python 3.10, 3.11 or 3.12 on Linux, macOS or Windows.

The fastest path: let Pylex choose

Install the light core package, then ask Pylex what your machine needs:

python -m pip install pylex-ocr
pylex doctor            # inspects CPU, NVIDIA GPU, TPU and installed packages
pylex doctor --install  # runs the recommended pip command (asks first)

pylex doctor prints the hardware it found, the runtime packages already installed, and the exact command to run. From Python the same thing is available as pylex.doctor(), so a notebook or deployment script can check itself.

If you run pylex before any OCR runtime is installed, the error message already contains the right command for your machine.

Pick one profile

Choose exactly one of these. They are alternatives, not add-ons.

Your hardware Install command What it installs
Any CPU (recommended default) pip install "pylex-ocr[cpu]" PaddleOCR, PaddlePaddle, ONNX Runtime
Intel CPU, to try OpenVINO pip install "pylex-ocr[intel]" PaddleOCR, PaddlePaddle, ONNX Runtime with the OpenVINO provider
NVIDIA GPU, nvidia-smi reports CUDA 13 or newer pip install "pylex-ocr[gpu]" PaddleOCR, PaddlePaddle, onnxruntime-gpu for CUDA 13, plus CUDA and cuDNN libraries from pip
NVIDIA GPU, nvidia-smi reports CUDA 12.x pip install "pylex-ocr[gpu-cu12]" The same, built for CUDA 12

These work the same for the command line tool and the Python SDK, because they are the same package.

Why one profile only? onnxruntime, onnxruntime-gpu and onnxruntime-openvino all provide the same Python module name. Installing two of them corrupts each other's files. If you switch hardware profiles, remove the old one first (see Switching profiles).

Which CUDA version do I have?

Run nvidia-smi and read CUDA Version in the top-right corner. That is the newest CUDA your driver supports, which is what matters here. You do not need the CUDA toolkit installed: the gpu extras pull the CUDA and cuDNN runtime libraries from pip.

  • 13.x or newer → [gpu]. ONNX Runtime's documentation says its CUDA 13.0 builds require CUDA 13.0 or newer, and that PyPI's onnxruntime-gpu has been built with CUDA 13.0 by default since version 1.27.
  • 12.x → [gpu-cu12], which pins ONNX Runtime below 1.27. The same documentation says builds made with CUDA 12.8 require CUDA 12.8 or newer, so if the GPU check below fails on an older 12.x driver, update the driver.
  • 11.x or older → the ONNX Runtime GPU builds Pylex installs target CUDA 12 and 13. Update the driver, or use the CPU profile.

Check that the GPU is really used

Having onnxruntime-gpu installed does not prove CUDA loads. ONNX Runtime silently falls back to the CPU if a CUDA or cuDNN library is missing, and Pylex hides backend output, so verify explicitly:

pylex doctor --verify-gpu

It builds a tiny model and asks ONNX Runtime which provider it actually registered. OK - CUDAExecutionProvider is active means you are on the GPU. Then run:

pylex scan.pdf --device gpu -v

or, in Python, Config(device="gpu"). See Using a GPU and GPU in the SDK.

Installing from GitHub

Before a release is on PyPI, or to try the latest code, install straight from the repository. Quote the whole thing:

python -m pip install "pylex-ocr[cpu] @ git+https://github.com/voltvirtuoso/pylex.git"

Replace [cpu] with [gpu], [gpu-cu12] or [intel] as needed. For development:

git clone https://github.com/voltvirtuoso/pylex.git
cd pylex
python -m pip install -e ".[cpu,dev]"
pytest

Use a virtual environment

OCR runtimes are large and version-sensitive. Keep Pylex in its own environment:

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install "pylex-ocr[cpu]"

To use only the command line tool, pipx isolates it for you:

pipx install "pylex-ocr[cpu]"

Paddle GPU build (alternative to ONNX Runtime)

Pylex can also run on the GPU through PaddlePaddle's own CUDA build, instead of ONNX Runtime. PyPI only carries paddlepaddle-gpu up to version 2.6.2 (checked October 2026); the 3.x GPU builds come from Paddle's own package index, so a pip extra cannot select them and you install in two steps. Copy the exact command for your CUDA version and platform from Paddle's installation guide; it has the form:

python -m pip install paddlepaddle-gpu==<version> -i <package-index-url-from-the-guide>
python -m pip install pylex-ocr "paddleocr>=3.0,<4"

Do not use the [ocr] or [cpu] extras here: they would also install the CPU paddlepaddle, which conflicts with paddlepaddle-gpu. Leave onnxruntime out as well, or add --inference-engine paddle_dynamic so Pylex does not pick it.

This route needs a system CUDA setup that matches the wheel. For most people the [gpu] profile above is simpler.

Other accelerators

PaddleOCR can target several accelerator types through its device setting, and Pylex passes the value through on the Paddle runtimes:

pylex scan.pdf --device npu:0 --inference-engine paddle_dynamic

Accepted device types are xpu, npu, mlu, gcu, dcu, iluvatar_gpu and metax_gpu, the device names PaddleOCR and PaddleX document. Each needs the matching hardware build of PaddlePaddle, installed from Paddle's instructions for that hardware. This path is passed through but has not been tested by the Pylex project, so treat it as experimental.

What Pylex does not use

Hardware Status
Google TPU Not supported. PaddleOCR's documented hardware list does not include TPUs, and Pylex has no TPU code path. On a TPU machine Pylex can only use the host CPU: install [cpu]. pylex doctor detects TPU environments from environment variables and says so.
Apple Silicon (Metal, Neural Engine) Pylex's extras run on the CPU; no Metal or Core ML provider is wired in. PaddleOCR documents Apple Silicon support through Paddle's own builds, which Pylex has not tested.
AMD GPUs (ROCm) Pylex's extras run on the CPU; no ROCm runtime is included. PaddleOCR documents AMD GPU support through Paddle's own builds, which Pylex has not tested.
Windows DirectML Not wired in. Runs on the CPU.

First run: models are downloaded

The first OCR run downloads the detection and recognition models and caches them under ~/.paddlex/official_models. After that, no network is needed.

  • The default download source is Hugging Face. To change it, set PADDLE_PDX_MODEL_SOURCE to huggingface, modelscope, aistudio or bos before running.
  • To skip the connectivity check, set PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True.
  • For an offline machine, run Pylex once on a connected machine and copy the ~/.paddlex folder across.

The first run with OpenVINO is also slower while the runtime compiles the models. It caches the result (see --runtime-cache-dir).

Switching profiles

To move from one profile to another, remove every ONNX Runtime package and then install the new profile:

python -m pip uninstall -y onnxruntime onnxruntime-gpu onnxruntime-openvino
python -m pip install "pylex-ocr[gpu]"

pylex doctor detects when more than one is installed and prints this for you.

Check the installation

pylex --version
pylex doctor

import pylex
print(pylex.__version__)
print(pylex.doctor())

The status line reads ready when the packages and providers match the recommended profile. If something is off, the report says what to change. See also Troubleshooting.

Quickstart

Five minutes from nothing to a searchable PDF, once from the command line and once from Python. Install first: Installation.

python -m pip install "pylex-ocr[cpu]"     # or [gpu], [gpu-cu12], [intel]

Command line

One scanned PDF

pylex scan.pdf -o scan-searchable.pdf

Without -o, Pylex writes scan.ocr.pdf next to the input. The first run downloads models, so it is slower than later runs. Open the output in any viewer and search or select text: the page looks the same, with an invisible text layer on top.

An image

pylex page.png -o page-searchable.pdf

PNG, JPEG, TIFF, BMP and WebP become single-page searchable PDFs.

A folder

pylex scans/ -r -o out/ -j 4

-r recurses, out/ mirrors the folder structure, -j 4 processes four files at once. Add --dry-run first to preview.

Dense or crowded pages

pylex drawing.pdf --tile-size 1000 --tile-overlap 250
pylex drawing.pdf --det-box-thresh 0.45 --det-unclip-ratio 2.0   # text touching line art

Use a GPU

pylex doctor --verify-gpu      # confirm CUDA really loads
pylex scan.pdf --device gpu    # or --device auto

Keep -j 1 with a GPU: worker processes compete for its memory.

Python

from pylex import Config, create_engine, extract_text

config = Config(model_size="small")
engine = create_engine(config)          # load once, reuse

for region in extract_text("page.png", config=config, engine=engine):
    print(f"{region.confidence:.2f}  {region.text}")

Each region has text, a confidence from 0 to 1, and a four-corner polygon in the image's pixel coordinates.

from pylex import create_searchable_document

result = create_searchable_document("input.pdf", "output.pdf", config=config, engine=engine)
if not result.ok:
    raise RuntimeError(result.error)
print(result.pages_processed, "pages,", result.lines_added, "lines")

For a GPU use Config(device="gpu").

Check the result

OCR is probabilistic. Search for words you know are on the page and look at confidence values for anything important. See Limitations.

Python SDK

Python SDK

Pylex is a library as well as a command. Everything the CLI does is available from Python, with the same install (Installation).

from pylex import Config, create_engine, extract_text, create_searchable_document

The three objects you need

  • Config: every setting, as a dataclass with sensible defaults.
  • engine: the loaded OCR backend from create_engine(config). Loading is slow (seconds); create it once and reuse it.
  • results: TextRegion objects from extract_text, or a FileResult from create_searchable_document.

extract_text

extract_text(source, *, config=None, engine=None, on_tile=None, on_tile_done=None) -> list[TextRegion]

source can be a file path, a PIL image, or a NumPy array (2-D grayscale or 3-D RGB; an alpha channel is dropped). NumPy arrays are assumed to be RGB. Large images are processed in overlapping tiles according to the config, and results are merged back into whole-image coordinates.

config = Config(model_size="small")
engine = create_engine(config)
regions = extract_text("page.png", config=config, engine=engine)
for r in regions:
    print(r.text, r.confidence, r.polygon.tolist())

TextRegion

Attribute Type Meaning
text str Recognized text for one line.
confidence float OCR confidence, 0 to 1. A signal, not proof of correctness.
polygon ndarray (4, 2) Four corner points (x, y) in original image pixels.

Regions are lines of text, not a document model: reading order, tables and headings are not reconstructed.

create_searchable_document

create_searchable_document(input_path, output_path, *, config=None, engine=None,
                           on_page=None, on_stage=None, on_tile=None, on_tile_done=None) -> FileResult

Takes a PDF or image and writes a searchable PDF.

Attribute Meaning
ok True when the output was written.
pages_processed Pages that were OCR'd (pages excluded by page_ranges are copied, not counted).
lines_added Text lines placed in the invisible layer.
error Error text when ok is false.
elapsed Seconds.
input_path, output_path The paths used.
failed_pages 1-based pages whose OCR raised an error. Those pages are kept unchanged, without a text layer.

A file can report ok=True and still have entries in failed_pages, so check it when completeness matters. The CLI exits with status 1 in that case.

Callbacks

Callback Called with When
on_page(page, n_pages) ints After each PDF page, including skipped ones.
on_stage(text) str Stage changes such as "Rendering page 2/10" or "Running OCR".
on_tile(n, total) ints Before a tile starts.
on_tile_done(n, total) ints After a tile finishes. 
from pylex import create_searchable_document
create_searchable_document("in.pdf", "out.pdf", config=config, engine=engine,
                           on_page=lambda p, n: print(f"page {p}/{n}"))

on_tile and on_tile_done apply to images; PDFs report through on_page and on_stage.

Lower-level functions

process_pdf(engine, input_path, output_path, cfg, on_page=None, on_stage=None) and process_image(engine, input_path, output_path, cfg, on_stage=None, on_tile=None, on_tile_done=None) do the work directly. They take pathlib.Path arguments and a Config, and return a FileResult.

GPU in the SDK

config = Config(device="gpu")          # "gpu:1" for a specific card, "auto" to use one if present
engine = create_engine(config)
regions = extract_text("page.png", config=config, engine=engine)

If the GPU is not usable, a warning explains why and the engine runs on the CPU (set allow_runtime_fallback=False to raise instead). Check beforehand:

import pylex
print(pylex.doctor())                          # readable report and install command
hw, rec = pylex.doctor(as_text=False)          # HardwareReport, Recommendation
ok, detail = pylex.verify_gpu()                # does CUDA really load?

rec.commands is the list of pip commands for this machine and rec.ready says whether it is already set up. Google TPUs are not supported; see Installation.

Recipes

Draw boxes on an image

from PIL import Image, ImageDraw
img = Image.open("page.png").convert("RGB")
draw = ImageDraw.Draw(img)
for r in extract_text(img, config=config, engine=engine):
    draw.polygon([tuple(p) for p in r.polygon.tolist()], outline="red")
img.save("boxes.png")

Export JSON

import json
data = [{"text": r.text, "confidence": r.confidence, "polygon": r.polygon.tolist()} for r in regions]
json.dump(data, open("page.json", "w"), ensure_ascii=False, indent=2)

Text from a PDF page without making a PDF

extract_text reads images, so render the page first:

import pypdfium2 as pdfium
page = pdfium.PdfDocument("doc.pdf")[0]
image = page.render(scale=300 / 72).to_pil().convert("RGB")
regions = extract_text(image, config=config, engine=engine)

Many files

Reuse one engine in a loop. For parallelism use separate processes, each with its own engine (the engine is not safe for concurrent calls from threads); the CLI's -j does exactly this.

Non-Latin searchable PDFs

config = Config(lang="ru", font="/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf")

For Chinese, Japanese or Korean use a built-in font such as font="STSong-Light".

Errors

  • A missing OCR backend, an unusable device with allow_runtime_fallback=False, or unreachable model hosts make create_engine raise pylex.PylexSetupError (a RuntimeError). The message says how to fix it, including the install command for your machine.
  • An unknown device or font raises ValueError.

Command line

CLI reference

pylex [options] INPUT [INPUT ...]
pylex doctor [--json] [--verify-gpu] [--install [-y]]

Run pylex --help for the authoritative list for your installed version. Inputs are PDF, PNG, JPEG, TIFF, BMP or WebP files, or folders. Output is always a searchable PDF.

Input and output

  • A single file with no -o gives <name>.ocr.pdf beside the input. Change the suffix with --suffix.
  • -o file.pdf names the output for a single input.
  • -o folder/ writes into a folder. With several inputs, or a folder input, -o is always treated as a folder, and a folder input has its structure mirrored.
  • Existing outputs are an error unless you pass --force (overwrite) or --skip-existing (skip).
  • Files are written to a temporary name first and then renamed, so a crash never leaves a half-written PDF.

Exit codes

Code Meaning
0 Every file succeeded
1 No matching input, nothing to do, a file failed, or OCR failed on some pages (the file was written but those pages have no text layer)
2 Invalid arguments

Selecting files

Using a GPU

pylex scan.pdf --device gpu        # first GPU
pylex scan.pdf --device gpu:1      # second GPU
pylex scan.pdf --device auto       # GPU if a CUDA runtime is installed, else CPU
pylex doctor --verify-gpu          # confirm CUDA actually loads

--gpu is a shortcut for --device gpu. With auto, Pylex picks ONNX Runtime when it has the CUDA provider, otherwise Paddle's GPU build. If you ask for a GPU that isn't usable, Pylex prints why and the fix, then continues on the CPU. Add --no-runtime-fallback to stop instead. Use -j 1 with a GPU; Pylex warns if you don't. Install steps are in Installation.

How it works

Pylex turns a page into a searchable page without changing how it looks. Each file goes through the same stages.

1. Render

A PDF page is rendered with pypdfium2 at --dpi (default 300), exactly as a viewer displays it, with the page's /Rotate value applied. A raster image is loaded as is.

2. Detect and recognize

The image goes to PaddleOCR models (PP-OCRv6 by default): a detector finds text lines, an optional classifier flips upside-down lines, and a recognizer reads each line. Pylex runs these through one of the runtimes below.

Runtime When it is used
ONNX Runtime (CPU or CUDA) Auto choice when installed. Fastest in the project's measurements on CPU.
ONNX Runtime with OpenVINO Auto choice when the OpenVINO build is installed ([intel]).
Paddle dynamic Fallback when ONNX Runtime is absent, or when only paddlepaddle-gpu provides the GPU.
Paddle static Only if requested explicitly. Can hit oneDNN operator errors on some builds.

With a GPU requested, auto selects ONNX Runtime if it has the CUDA provider, otherwise Paddle's GPU build; if neither exists it explains the fix and continues on the CPU.

3. Tiling for dense pages

A whole-page pass shrinks the page to the detector's size limit, which can make small labels squeezed between symbols too small to detect. Pylex instead cuts large pages into overlapping tiles (--tile-size, default 2000 px; --tile-overlap, default 220 px), runs OCR on each at full resolution, shifts the results back into page coordinates, and merges duplicates: the same text whose centers lie within --dedupe-tol-px is kept once, with the highest confidence.

Images no larger than one tile are not tiled. For --model-size small, an adaptive shortcut also skips tiling when the image fits the detector limit and 8 megapixels; --strict-tiling turns that off.

4. Vertical text retry

The orientation classifier only distinguishes 0 and 180 degrees, so text running vertically is often misread. When a tile contains tall, low-confidence boxes, Pylex re-runs that tile rotated 90 degrees and merges the better results. Disable with --no-vertical-text-retry.

5. Build the invisible layer

For each recognized line, Pylex draws the text in PDF text render mode 3 (invisible). The font size comes from the box height, the horizontal scale stretches the text to the box width, and the angle follows the polygon. Each line is anchored at the start of its polygon, so long text cannot drift off the page.

6. Merge without disturbing the page

For rotated PDF pages, Pylex first transfers /Rotate into the page content, so the overlay and the OCR image share one orientation, then merges the overlay onto the original page. The visible content is never re-rendered or re-compressed. Output is written to a temporary file and renamed.

Parallelism

-j N runs N worker processes, each loading its own engine. Pages inside one PDF are sequential. CPU threads are divided between workers automatically unless you set --cpu-threads.

Fonts

The text layer uses Helvetica by default, which covers Latin-1. Other scripts need --font with a Unicode TrueType file or a built-in CJK font. See CLI reference.

Accuracy and benchmarks

Speed and quality depend on the document, resolution, language, model, runtime and hardware. Use this page to choose settings, and to publish measurements that others can reproduce.

Choosing settings

Goal Start with Trade-off
Best general accuracy CLI default (--model-size medium) More CPU time and memory
Balanced speed --model-size small Adaptive full-page pass for images up to 8 MP
Simple, clean image, fastest --fast Weaker on dense, rotated or noisy pages

Comparison with other tools

benchmarks/compare.py builds scan-like test pages with known word positions, runs Pylex, OCRmyPDF with Tesseract, and OCRmyPDF with the ocrmypdf-paddleocr plugin from PyPI (ocrmypdf --plugin ocrmypdf_paddleocr; OCRmyPDF's own page also lists a different PaddleOCR plugin, so say which one you used), and scores each text layer:

  • Recall: share of true words whose text appears in the layer, wherever it is.
  • Aligned: share found in the right place (word centre within 0.6 line-heights vertically and 4 horizontally).
  • Extra: OCR words that match no true word.

Cases: a plain text page, a dense page of small labels with line work, and the plain page stored sideways with /Rotate 90 and /Rotate 270. Every test word carries a unique tag so chance matches stay near zero. The scoring itself is verified with a perfect-text-layer oracle at all four rotations (--self-test).

python benchmarks/compare.py                                   # every installed tool
python benchmarks/compare.py --only pylex --pylex-args "--device gpu"
python benchmarks/compare.py --input-dir my-scans/             # your own files: timing and word counts

Result so far: OCRmyPDF with Tesseract

Measured on a single-core Linux sandbox, OCRmyPDF 17.13 with Tesseract 5 and the English model. Synthetic pages, so read these as a baseline for the harness, not as a verdict on any tool.

Measuring quality

Use a permission-cleared validation set and report a defined metric such as character or word error rate. Keep evaluation data separate from the data you tuned on. For searchable PDFs also test text-layer alignment on rotated pages. Do not generalize from one document or one machine.

Limitations

Pylex runs OCR on raster images and rendered PDF pages, then adds the recognized text to a searchable PDF or returns regions through the Python API. It suits scans, screenshots, forms, receipts, diagrams, technical drawings and photographs.

OCR is probabilistic

Results can be wrong for handwriting, very small, blurred, skewed, noisy, low-contrast or occluded text, and for languages without the right model. Confidence scores help find uncertain regions but do not prove correctness. Validate output on representative documents when errors have operational, legal, safety or financial consequences.

What Pylex does not do

  • No handwriting recognition, translation, table reconstruction, semantic headings or guaranteed reading order.
  • No PDF/A output, deskewing or image clean-up. If you need those, OCRmyPDF is a better fit.
  • It is a library and CLI, not a hosted OCR service.

Scripts and fonts

The invisible text layer defaults to Helvetica, which covers Latin-1. Other scripts need --font with a Unicode .ttf or a built-in CJK font. Right-to-left scripts such as Arabic and Hebrew are not verified: shaping and ordering in the text layer may not match what a reader expects.

Hardware

CPUs and NVIDIA GPUs (CUDA, through the [gpu] profiles) are what Pylex's install profiles support. Google TPUs are not supported. Apple Silicon, AMD and DirectML GPUs run on the CPU in Pylex. Other Paddle accelerator types are passed through to PaddleOCR but untested.

Failure handling

If OCR fails on a PDF page, Pylex keeps the page unchanged, logs a warning and records it in FileResult.failed_pages; the file is still written. The CLI then exits with status 1 and names the pages. create_engine raises PylexSetupError when no backend is installed.

Sensitive documents

Process sensitive files in an appropriate environment and do not attach them to public issues. Models are downloaded on first use; after that no network is needed.

Troubleshooting

Start with pylex doctor. It lists the hardware found, the packages installed, and the command to fix the setup.

"paddleocr is not installed"

No OCR runtime is installed. The message includes the command for your machine; or run pylex doctor --install. Do not use pip install pylex (an unrelated project).

pip cannot find pylex-ocr

If no release is on PyPI yet, install from GitHub: pip install "pylex-ocr[cpu] @ git+https://github.com/voltvirtuoso/pylex.git".

I asked for the GPU but it runs on the CPU

Pylex prints a warning saying why. Common causes:

  • Plain onnxruntime is installed. It has no CUDA. Run pip uninstall -y onnxruntime, then pip install "pylex-ocr[gpu]".
  • Two ONNX Runtime packages are installed. doctor flags this. Uninstall all of onnxruntime, onnxruntime-gpu, onnxruntime-openvino, then install one profile.
  • CUDA libraries did not load. Run pylex doctor --verify-gpu. If it says the provider is listed but did not load, your driver is probably too old for the build. Check nvidia-smi: CUDA 13 needs [gpu], CUDA 12 needs [gpu-cu12].
  • No NVIDIA GPU. Intel, AMD and Apple hardware run on the CPU in Pylex, and TPUs are not supported. See Installation.

To confirm the GPU is busy while a job runs, watch nvidia-smi.

--gpu is slower with -j 4

Workers share one GPU and compete for memory. Use -j 1 with a GPU.

The search finds nothing, or text is garbled

  • Non-Latin scripts (Russian, Greek, Chinese, Arabic...) need --font. The default font only covers Latin-1, and Pylex logs a warning when it meets other characters.
  • No text detected: try --retry-upscale, a higher --dpi, or lower --det-box-thresh.
  • A page was kept unchanged: if OCR fails on a page, Pylex logs a warning, keeps the page without text, and exits with status 1 naming the pages (FileResult.failed_pages in Python). Run with -v to see the cause.

Small labels are missed on a dense drawing

Use smaller tiles and a more tolerant detector: --tile-size 1000 --tile-overlap 250 --det-box-thresh 0.45 --det-unclip-ratio 2.0.

The first run is very slow

Models are being downloaded (cached in ~/.paddlex/official_models), and OpenVINO compiles models on first use. Later runs are faster. Choose a different download host with PADDLE_PDX_MODEL_SOURCE=modelscope (or aistudio, bos), or copy ~/.paddlex from a connected machine for offline use.

"No available model hosting platforms detected"

Pylex prints "could not download its OCR models". The machine cannot reach any model host. Allow access to one of them, set PADDLE_PDX_MODEL_SOURCE, or copy a populated ~/.paddlex.

Output already exists

Pass --force to overwrite or --skip-existing to skip.

oneDNN or PIR errors with Paddle static

Use the default runtime, or --inference-engine paddle_dynamic. Pylex retries dynamic Paddle automatically unless --no-runtime-fallback is set.

Reporting a problem

Include pylex --version, the output of pylex doctor, the exact command, the input type and resolution, and a redacted or synthetic example. See CONTRIBUTING.
